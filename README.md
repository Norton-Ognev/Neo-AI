# NeoAI

> Умный ежедневник с голосовым вводом, который работает **полностью локально**: без интернета после установки моделей, без платных API и без отправки данных на сторонние серверы.

Neo — голосовой ассистент для управления задачами, напоминаниями и встречами. Скажите «Напомни завтра в 10 позвонить Ивану» — и задача окажется в ежедневнике. Всё распознавание речи, понимание запроса и синтез ответа происходят на вашем компьютере даже без интернета.

## Возможности

  

| Сценарий                    | Пример фразы                                                   |
| --------------------------- | -------------------------------------------------------------- |
| Создание задачи/напоминания | "Напомни завтра в 10 позвонить Ивану"                          |
| Создание встречи            | "Добавь встречу с командой 28 ноября в 15:00"                  |
| Список событий за период    | "Что у меня сегодня?", "Какие задачи на ближайшие две недели?" |
| Поиск старых записей        | "Найди задачу про презентацию"                                 |

Дополнительно:

- **Уточняющий диалог.** Если данных не хватает, Neo не угадывает, а спрашивает: «На какое время поставить встречу?»

- **Wake word «Привет, Нео».** Приложение висит в фоне, слушает микрофон и активируется голосом — либо по кнопке записи (push-to-talk).

- **Озвучка ответов.** Ответ не только показывается в интерфейсе, но и произносится (Silero TTS).

- **Автозапуск, микрофон и динамики, громкость Нео.** Всё регулируется в настройках.

## Установка

### Вариант 1. Готовый инсталлятор

  
1. Откройте [раздел Releases](../../releases) и скачайте последний `NeoAI-Setup-x.x.x.exe`.

2. Запустите инсталлятор и следуйте шагам мастера.

3. При первом запуске приложение докачает модели (~8 ГБ).

> Инсталлятор весит ~150 МБ: бинарники и код внутри, модели докачиваются отдельно. Это сознательное решение — см. [«Решения, принятые самостоятельно»](#решения-принятые-самостоятельно).

**Системные требования**

| ОС        | Windows 10 / 11, x64                                       |
| --------- | ---------------------------------------------------------- |
| Процессор | x64 с поддержкой AVX2 (инференс идёт на CPU)               |
| ОЗУ       | от 8 ГБ; для комфортной работы LLM рекомендуем 16 ГБ       |
| Диск      | ~8 ГБ на приложение и модели                               |
| Микрофон  | для голосового ввода (текстовый режим работает и без него) |

### Вариант 2. Сборка из исходников

Потребуется **Python 3.11 (x64)** — версия важна.

```powershell
# Виртуальное окружение
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Зависимости
.\.venv\Scripts\python -m pip install --upgrade pip
.\.venv\Scripts\python -m pip install -r neo/requirements.txt pyinstaller

```

  
**Запуск из исходников** (точка входа — `run_neo.py`):

```
.\.venv\Scripts\python run_neo.py
```

**Сборка `.exe` через PyInstaller:**

```

Remove-Item -Recurse -Force .\build, .\dist -ErrorAction SilentlyContinue

Remove-Item -Force .\NeoAI.spec -ErrorAction SilentlyContinue

  

.\.venv\Scripts\python -m PyInstaller --noconfirm --clean --onedir --windowed --name NeoAI `

  --add-data "neo/frontend;neo/frontend" `

  --add-data "neo/ai/prompts;neo/ai/prompts" `

  --collect-submodules neo --collect-submodules uvicorn `

  --collect-all faster_whisper --collect-all ctranslate2 --collect-all av `

  --collect-all vosk --collect-all webview --collect-all sounddevice `

  --collect-submodules omegaconf --collect-data omegaconf --copy-metadata omegaconf `

  --hidden-import omegaconf --hidden-import omegaconf.errors --hidden-import omegaconf.nodes `

  --hidden-import win32com.client `

  --runtime-hook runtime_hook_arch.py `

  run_neo.py

```

Готовое приложение появится в `dist/NeoAI/`. Сборка инсталлятора — Inno Setup, скрипт лежит в `neo/installer/neo.iss`.

## Первый запуск

1. **Модели.** При первом старте приложение скачивает STT/TTS/VAD-модели (~7 ГБ) в локальную папку и показывает прогресс. Нужен интернет — один раз.

2. **LLM.** Рантайм Ollama **вшит в дистрибутив** и запускается приложением автоматически — отдельно скачивать или устанавливать Ollama не нужно. Пользователь ничего не настраивает: приложение само поднимает локальный Ollama на `127.0.0.1:11434`.

## Архитектура

### Три принципа, на которых всё держится

1. **LLM не ходит в базу данных.** Модель только классифицирует интент и вытаскивает слоты в структурированный JSON. Все операции с данными выполняют Python-сервисы. Это делает поведение предсказуемым и тестируемым: галлюцинация модели не может испортить записи в БД.

2. **Один вход в AI — `orchestrator.py`.** Все обращения к LLM идут через него, прямых вызовов модели в других модулях нет.

3. **UI ничего не знает про LLM.** Фронтенд общается только с REST API на localhost. Внутри — чёрный ящик, который можно дёргать хоть через `curl`.

### Порты

| Сервис            | Адрес                                                  |
| ----------------- | ------------------------------------------------------ |
| Backend (FastAPI) | `127.0.0.1:8000` — только localhost, наружу не смотрит |
| Ollama            | `127.0.0.1:11434` (по умолчанию)                       |

## Решения, принятые самостоятельно

Ниже — то, чего не было в задании в явном виде, но что мы выбрали осознанно.

**1. Разделили «понимание» и «действие».**

LLM не трогает базу данных: она возвращает только интент и слоты в JSON, а создание, выборка и поиск — это обычный Python-код в сервисах. Так мы получили три вещи: предсказуемость (модель не может «придумать» запись), тестируемость (сервисы покрыты юнит-тестами без запуска LLM) и простую заменяемость модели.

**2. Двухступенчатое распознавание речи.**

Сначала дешёвый VAD отсекает тишину, затем Vosk по узкой грамматике ловит «привет нео», и только после этого запускается тяжёлый Whisper. На CPU это критично: большую модель мы гоняем секунды, а не постоянно.

**3. Wake word на Vosk, а не на отдельной нейросети.**

Модель на 45 МБ и грамматика из одной фразы дают нужный результат без ещё одного ONNX-инференса в фоне. Экономия и по размеру дистрибутива, и по CPU.

**4. Уточняющий вопрос вместо догадки.**

Если модель не вытащила время встречи — ассистент спрашивает. Для ежедневника это важнее «магии»: лучше один лишний вопрос, чем задача, созданная не на тот день.

**5. Модели не в инсталляторе.**

Инсталлятор ~150 МБ, модели (~6 ГБ) докачиваются при первом запуске. Причина pragmatic: лимиты GitHub Releases и время скачивания; плюс пользователь видит прогресс и понимает, что происходит.

**6. REST API вместо прямых вызовов из UI.**

Фронтенд не знает про LLM и модели вообще. Побочный плюс: любой сценарий можно проверить через `curl` и `http://127.0.0.1:8000/docs`, не поднимая интерфейс.

**7. pywebview вместо Electron.**

Дистрибутив и потребление памяти меньше в разы, а требования к UI у нас скромные — HTML/CSS/JS закрывают их полностью.

**8. Ollama как рантайм LLM.**

Не тащим инференс-движок внутрь exe: модель и веса живут отдельно, обновляются независимо от приложения.

## Что улучшили бы при наличии времени

**Продукт**

- **Контекст диалога.** Сейчас «перенеси её на завтра» не работает — каждый запрос самостоятельный. Нужна короткая история диалога и резолвинг местоимений. Имеются проблемы со склонениями слов в названии мероприятий. 

- **Повторяющиеся события.** «Каждый понедельник в 10» — самая частая просьба для ежедневника. Требует RRULE-подобной модели в БД.

- **Семантический поиск на эмбеддингах.** Сейчас поиск лексический. Эмбеддинги дали бы «найди задачу про презентацию» → «подготовить слайды к совету директоров».

- **Интеграция с календарями** (Google Calendar / CalDAV) — но это уже конфликтует с принципом «полностью офлайн», так что только как opt-in.

- **Светлая тема и настройка горячих клавиш.**

- Запись и создание более живого голоса при помощи данных одного из членов команды


**Инженерия**

- **Стриминг ответа LLM.** Первые токены можно показывать сразу, а не ждать полный JSON — субъективно 5–15 секунд ожидания превратятся в 1–2.

- **Стриминг TTS по предложениям** и кэш озвучки частых фраз.

- **Автообновление** через встроенный updater вместо ручного скачивания релиза.

- **Разделить сборку**: сейчас PyInstaller и Nuitka соседствуют, стоит выбрать один путь и довести его до конца.

- **Логи и локальная диагностика** — кнопка «собрать отчёт» для баг-репортов.

**Качество**

- **NLU-корпус и регрессия по фразам.** Набор из 200–300 живых формулировок с ожидаемым интентом и слотами — чтобы правка промпта не ломала соседние сценарии.

- **Замеры latency по этапам** (VAD → wake word → STT → LLM → TTS) в CI на эталонном железе.

- **Тесты на «плохие» входы**: шум, обрыв фразы, два интента в одном предложении.

## Известные ограничения

- Только **Windows x64** и только **русский язык**.

- Нет контекста диалога и повторяющихся событий (осознанно вне скоупа первой версии).

- Инференс на CPU: обработка запроса занимает **5–15 секунд** в зависимости от железа. UI в это время показывает состояние «обрабатываю».

- Первый запуск требует интернета для скачивания моделей (~6 ГБ).

- Многопользовательский режим не поддерживается: база — локальный файл одного пользователя.
